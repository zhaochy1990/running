# 赛道距离与爬升的计算方法

从**举办方公布的路线文字链**（或 GPX/KML 轨迹）算出赛道的**距离**与**累计爬升/下降**，
产出 `RaceCalendarItem.TotalAscentM` 与 `ElevationPoints`。

本文记录方法、参数、验证结果和已知限制。参数不是调优出来的默认值，而是**用实测赛事
反推标定的**——换参数结果会成倍漂移，所以口径本身就是产品定义，必须硬编码并留档。

## 结论摘要

**距离**：文字链 → 交叉口 POI → 路径规划 → polyline。
**爬升**：DEM 采样后必须强滤波。原始采样输出纯属噪声，**不可用**。

```
滤波链:  中值滤波 210m → 均值滤波 310m → 阈值 3m 迟滞累加
```

三场验证 —— **全部由举办方文字路线计算**。轨迹文件（GPX/KML）只作交叉校验，
不参与产出：文字链是官方发布的形态，可自动获取且逐年更新；轨迹文件来源不可控、
覆盖不全，不能作为数据生产的依赖。

| 赛事 | 官方距离 | 本方法 | 偏差 | 真实爬升 | 本方法 | 结果 |
| --- | --- | --- | --- | --- | --- | --- |
| 西安马拉松 | 42.195 | 42.480 | +0.285 | 40–60m（跑者手表） | 49m | ✅ |
| 上海马拉松 | 42.195 | 42.650 | +0.455 | 30–50m（实测） | 37m | ✅ |
| 杭州马拉松 | 42.195 | 43.249 | +1.054 | 100–131m（组委会公布） | 89m | ⚠️ 偏低 11–32% |

### 能力边界：排序可靠，绝对值不可靠

**没有任何一组滤波参数能同时命中三场**（已做完整扫描）：

```
中值210m+均310m 阈值3m   西安49✅  上海37✅  杭州89 ✗
中值150m+均210m 阈值3m   西安66    上海65✗   杭州113✅

真实比值(杭州/上海) = 2.9x
方法比值            = 2.0x (强滤波) ~ 1.3x (弱滤波)
```

**动态范围被压缩**：滤波越强压缩越厉害，但即使最强也追不上真实的 2.9x。
根因是 30m DEM 的分辨率——杭州的爬升集中在复兴大桥、钱塘江大桥、虎跑路坡道
这些**短距离陡升**上，而强滤波恰恰把它们与噪声一起抹平。

**排序三场全对**：

```
真实  杭州(115) > 西安(50) > 上海(40)
方法  杭州(89)  > 西安(49) > 上海(37)   ✓ 一致
```

**因此功能定位为「难度分级与排序」，不展示精确数值。** 具体表达见第六节。

## 一、输入

三种，优先级从高到低：

1. **真实轨迹（GPX/KML）** —— 最准。几何无需构建，直接进入第 3 步。
2. **举办方文字链** —— 中国赛事的常见形态。典型如西安：
   `永宁门南广场（起点）→南大街→钟楼盘道→…→奥体中心体育场（终点）`，
   折返标注为自由文本（`上善巷折返处（折返）`）。
3. **赛事官网零散描述** —— 只有起终点和主要道路，无法构建完整几何。杭州马拉松即属此类。

> 注意路线**逐年变化**。西安 2025 与 2026 的浐灞段不同（2026 走永泰路→灞三路→浐灞大道），
> 折返点名称也有微调。计算必须绑定到具体年份的路线。

## 二、几何构建（输入为文字链时）

### 2.1 把路段转成转向点

**核心手法：相邻两路段隐含一个交叉口，用交叉口做途经点，而不是路名。**

```
太华北路 → 永顺路      ⇒    搜「太华北路与永顺路交叉口」
                                     ⇒ 108.971643,34.317081   ✓ 精确命中
```

为什么不能用路名：高德对「路的代表点」返回的是该路的**任意位置**，不是途经位置。
西安的实测结果——

```
太华北路 34.34 → 永顺路 34.317 → 御井路 34.348 → 永隆路 34.327
   文字顺序如此，纬度却先降后升再降 → 顺序错乱 → 路径规划多绕
```

**只保留真正的转向点。** 路网必经的中间点（如钟楼在「南大街→东大街」上）必须删掉，
否则途经点落点偏差会逼路径绕行：

```
起点→钟楼→东门   4.50 km   ← 保留钟楼
起点→东门        3.48 km   ← 删掉钟楼，省 1.02 km
理论值(南大街1.2+东大街2.2) = 3.4 km
```

同样，长段直连优于逐段拼接：

```
起点→东门→环城东×太华→太华×永顺   9.96 km   ← 逐段
起点→太华×永顺                   9.73 km   ← 直连，理论值 9.77
```

### 2.2 折返段：先分清「V 形」和「往返」

路径规划 API 不会原路掉头，它会找环路。但**折返不等于「去+回」**——必须按折返点
在路径中的位置分两类处理。**这个区分是距离准确性的关键，混淆会多算数公里。**

**V 形（折返点即路径最远端，占绝大多数）**

折返点本身就是路径序列上的一个点，规划 A→B→C 时自动包含了折返。**不能额外加往返。**

上海龙腾大道就是典型：从瑞宁路(31.1844) 南下到进木港路(31.1334) 折返，再北上
到丰谷路(31.1711) —— 这是一条 V 形路径。按「去+回」处理会多算 6.15km：

```
正确  A→B→C 逐段规划      42.650 km  (+0.455)  ✅
错误  A→B 再手工加 B→A    53.022 km  (+10.827) ❌
```

**往返（折返点不在路径序列上，需要专程跑一段再回来）**

只有这种情况才手工插入原路往返：

```python
poly = poly[:j+1] + forward[1:] + forward[::-1][1:] + poly[j+1:]
```

判断依据：折返点在文字链里是**独立的一段**（如西安 `上善巷→上善巷折返处→上善巷`），
而不是相邻两段之间的一个节点。

**折返点位置文字链往往不给**（「赛道1.7KM处折返」），需要从官网公告、赛道图或
分年路线描述里确认。上海 2024 年的描述就比 2023 精确：
`龙腾大道（进木港路折返）` 直接给出了折返所在的道路。

### 2.3 走行方式选择

**逐段取 `min(walking, driving距离优先)`。**

- `walking` 走人行道，每个路口绕斑马线，约 30 个路口累积多走 ~1km
- `driving` 走机动车道更直，但受单行道限制，在辅路/立交处会严重绕行
  （实测有 ratio 4.09 的段：直线 0.54km 走成 2.19km）

两者各有盲区，逐段取短者最接近「最短路径」——马拉松赛道正是按最短路径丈量的
（2024 年西马还专门画了引导蓝线）。`bicycling`/`electrobike` 实测无优势。

### 2.4 坐标转换

高德返回 **GCJ-02**，必须转 **WGS84**（DEM 是 WGS84）。前端已有 `gcoord`，
`frontend/src/components/maps/coordTransform.ts` 可复用。

西安实测偏移 463–481m，但**高程只差 ±3m**（城区太平）——该转，但不是致命项。

## 三、高程采样

### 3.1 DEM 选择

| 数据集 | 结论 |
| --- | --- |
| **Copernicus GLO-30** | **采用**。TanDEM-X，垂直精度优于 SRTM。S3 免 key 直连 |
| SRTM 30m / Mapzen | 同源，精度不足（标称 ±16m） |
| ASTER GDEM | 城区噪声爆炸（阈值5m 给 1303m），不可用 |

```bash
# 1°×1° 分块，西安用 N34E108/N34E109，上海用 N31E121
curl -O "https://copernicus-dem-30m.s3.amazonaws.com/\
Copernicus_DSM_COG_10_N34_00_E108_00_DEM/Copernicus_DSM_COG_10_N34_00_E108_00_DEM.tif"
```

3600×3600 float32，PIL 可直接读（无需 rasterio）。像素换算：

```python
px = (lon - tile_lon) * 3600 - 0.5      # 像素中心
py = (tile_lat_top - lat) * 3600 - 0.5
```

**它是 DSM（含建筑/树冠）**，城区会系统性偏高：西安东大街 421m（实际约 400m）。
这正是必须强滤波的原因之一。

### 3.2 采样密度

**10m 等间距重采样。** 已收敛，再加密无收益：

```
采样间距   点数     阈值5m爬升
  5m      8545      +175m     ← 迟滞算法在过密采样下反而低估
 10m      4273      +209m     ← 收敛值
 20m      2137      +209m     ← 与 10m 一致
```

## 四、滤波与累计（关键步骤）

### 4.1 为什么必须强滤波

**DEM 噪声（±3–4m）与赛道真实起伏（3–10m）同量级。** 两份独立 DEM 的分歧：

```
城区 0-11km   平均 3.0m   最大 23.7m
浐灞 11-42km  平均 4.4m   最大 21.1m
```

决定性证据——拿一份**独立的真实轨迹**（上海，540 点导航线，自算 42.435km，
与本方法文字链几何只差 0.215km）做交叉校验，原始采样输出仍是 **417m**，
而真实值 30–50m。**所以问题与几何精度无关，纯粹是噪声。**

同理，杭州用文字链几何采样，原始输出 911m（阈值3m），而真实值 100–131m。
两场都指向同一结论：不滤波的 DEM 输出不可用。

### 4.2 滤波链

```python
def median_filter(v, w):      # w = 21 (210m)
    h = w // 2
    return [statistics.median(v[max(0,i-h):i+h+1]) for i in range(len(v))]

def mean_filter(v, w):        # w = 31 (310m)
    h = w // 2
    return [statistics.mean(v[max(0,i-h):i+h+1]) for i in range(len(v))]

def climb(v, th=3.0):         # 迟滞累加
    up = dn = 0; anchor = v[0]
    for x in v[1:]:
        if abs(x - anchor) >= th:
            d = x - anchor
            up += max(d, 0); dn += max(-d, 0)
            anchor = x
    return up, dn

elev = climb(mean_filter(median_filter(elev, 21), 31), 3.0)
```

`Threshold` 用迟滞而非逐点比较：只有确认变向才更新锚点，避免噪声反复触发。

### 4.3 参数敏感性（为什么口径即定义）

同一份上海几何，换滤波参数：

```
原始(阈值5m)              +417m
中值210m+均值310m+阈值3m   + 37m   ← 采用
中值310m+均值410m+阈值3m   + 34m
```

**从 34m 到 417m 都能「算出来」**，差 12 倍。所以参数不是可调项，是产品定义。

标定用了三场已知真实值的赛事，**没有任何一组能同时命中三场**：

```
滤波链                阈值   西安     上海     杭州     参考区间
                            40-60m  30-50m  100-131m
中值210m+均值310m       3m   49 ✅   37 ✅   89 ⚠️    两中 ← 采用
中值150m+均值210m       3m   66      65      113 ✅   一中
中值90m                 5m  155     190      243      全高
```

采用 `中值210m + 均值310m + 阈值3m`：两场命中、杭州偏低 11–32%，
是综合最优的一组，且**三场排序完全正确**。

## 五、已知限制

1. **标定样本只有三场。** 参数在西安、上海成立，杭州偏低，说明它偏向低爬升赛道。
   新增有实测值的赛事必须回归验证，尤其是爬升 > 150m 的赛道。

2. **动态范围被压缩。** 方法给出的杭州/上海比值（2.0x）低于真实的 2.9x。
   过滤波参数只能改善不能消除——这是 30m DEM 分辨率的硬约束。

3. **物理可解释性未证实。** 上海 37m 里多少是龙腾大桥的真实信号、多少是残余噪声，
   无法区分——强滤波窗口（520m）与桥长同量级。

4. **30m DEM 测不出桥面本身**，只能靠桥前后地面高程差间接体现。精度天花板在此。
   杭州偏低即源于此：它的爬升集中在复兴大桥、钱塘江大桥、虎跑路坡道的**短距离陡升**上。

5. **城区段有残留偏差。** 即使最强滤波，平坦市区仍算出 22–35m——DSM 的建筑噪声消不干净。

6. **文字链的折返点位置常缺失**，且「V 形」与「往返」必须分清（见 2.2），
   否则距离会偏出数公里。

## 六、产品落地要求

**核心原则：这个能力用于「分级与排序」，不用于「精确数值」。** 三场验证证明排序可靠、
绝对值有 ±30% 级误差，UI 必须按此设计，否则上海赛道会显示成 407m 这种读起来正常、
跑过的人一眼知道是错的数字。

1. **口径硬编码**并写进代码注释。参数即定义，换参数结果从 34m 漂到 417m。

2. **`ascent_source` 三态**：`organiser`（官方公布）/ `measured`（用户 GPX）/
   `estimated`（DEM 推算）。三态在 UI 上必须可区分。

3. **`estimated` 用分级而非数值表达**：

   | 分级 | 阈值（本方法输出） | 三场落点 |
   | --- | --- | --- |
   | 平坦 | < 60m | 上海 37m / 西安 49m |
   | 起伏 | 60–120m | 杭州 89m |
   | 多坡 | > 120m | （暂无样本） |

   分界值取 60m 与 120m：前者让西安(49) 与上海(37) 同档而杭州(89) 单列，
   与真实难度排序一致；后者留出预警——本方法在 > 150m 的赛道上未经标定（见第五节）。

4. **数值表达留余地**：确需展示时用「爬升约 50m」，不用「爬升 49m」。

5. **净爬升可精确展示**。一阶差分不累积噪声，三场都稳定：

   ```
   上海   起点 2.1m → 终点 3.7m     净 +1.6m
   西安   起点 404.8m → 终点 374.2m  净 -30.6m
   杭州   起点 8.8m  → 终点 4.9m     净  -3.9m
   ```

6. **赛后用用户 GPX 覆盖**为 `measured`。这才是累计爬升的正解——手表气压计精度 ±1m，
   远胜任何公开 DEM。**你们有用户，这是别家没有的优势。**

7. **官方公布了爬升时直接采信**，标记 `organiser`（如杭州 131m）。
   官方数字优先级永远高于本方法。

## 七、复现清单

```
需要: python3 + PIL + numpy

1. 几何   相邻路段 → 搜「A与B交叉口」→ 途经点

2. 坐标   GCJ-02 → WGS84

```

## 附三：轨迹文件的正确定位

西安、上海、杭州都曾找到过 KML/GPX，但**它们不参与数据产出**：

- **来源不可控**：网上流传的轨迹不保证与丈量赛道一致，且不是每场都有
- **自带高程不可用**：上海 KML 的高程列是 5~39m（大量 9.0），而上海实际 2–5m，
  属 GPS 采集高度，噪声 ±10m
- **覆盖不全**：杭州的 KML 只有 6 个点，无 LineString

它们的正确用途是**交叉校验**：上海 KML 的 540 点导航线自算 42.435km，
与本方法的 42.650km 相差 0.215km，说明几何构建是可靠的。

**数据生产必须依赖文字链**——它是官方发布的形态、可自动获取、逐年更新。
