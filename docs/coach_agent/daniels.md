# 丹尼尔斯训练法·训练计划生成——总设计文档

> 本文是**总览**：架构全景、共享词汇、跨层决定、层间契约。各层详细设计见分文档（文末索引）。
> 治理规则：所有文档只记录**已拍板**的决定；未定、待验证、未经确认的方案不进文档；决定变更时直接修改并更新日期。

## 1. 架构全景（生成侧三层出政策包 + 执行侧 L4/L5 与回路）

```
教义（本总览 + 各层文档 = 单一来源，所有层的 prompt 与规则出处）

── 生成时（一次性，产物=政策包：L2 意图 + L3 周骨架 + 块标记 + 政策；不含课表明细）──
L1 证据层     纯代码   buildPhaseEvidence：画像/当前能力/常态基线 habitual    → 已合并
L2 阶段划分层  LLM×1    五阶段+里程碑+体量带+块模式 ｜ 结构门+T 兜底          → 已合并
L3 载荷层     纯代码   周骨架+块标记+回补策略+力量policy+六门（38 案例验证）   → 已合并

── 执行时（块界生成 + 每夜复盘；L4/L5 归此处）──────────────
L4 内容层     LLM×1/块  周骨架→具体课表：结构=课表库缺省+LLM 选择适配，配速=VDOT 六带确定性
L5 落位层     纯代码   scheduler 排日 + 验收门终检
R0 每夜复盘    纯代码   完成度/偏差信号采集与路由（确定性阈值，超限才升级）
R1 块界生成    L4+L5   块（3+1）到界一次生成整块课表；偏差触发重生成未执行部分
R2 块边界级    每~4周：读 L3 的回补策略选场景 → 影响下一块
R3 结构级     伤停/改期/换目标 → 重发 L2（一次小调用，便宜）
```

判断与构造的分布是架构核心：LLM 只在 L2（赛季 1 次）与 L4（每块 1 次），其余全确定性——「把过门变成构造问题」。每层自带验收门，失败各自回炉自己的层。

## 2. 共享词汇：canonical 阶段枚举（定稿 5 值）

阶段命名对齐 Daniels' Running Formula（弃用 base/speed/build/marathon 旧枚举——Friel 体系混搭且泄漏距离），详细合同见 L2 分文档：

| canonical | 中文显示名 | 丹尼尔斯原文 | 职能 |
|---|---|---|---|
| `recovery` | 恢复期 | （无，本体系显式补充） | 赛后卸疲劳 |
| `foundation` | 第一阶段·基础期 | Phase 1 Foundation | E 跑+strides+轻爬坡，地基与防伤 |
| `early_quality` | 第二阶段·早期质量期 | Phase 2 Early Quality | R 重复跑，跑姿经济性与速度 |
| `transition_quality` | 第三阶段·过渡质量期 | Phase 3 Transition Quality | I 间歇为主，T 开始上量 |
| `final_quality` | 第四阶段·最终质量期 | Phase 4 Final Quality | T+M 比赛专项，自带 taper（属性非阶段） |

- 训练强度词汇沿用 **E/M/T/I/R**（丹尼尔斯原生）。
- **出处分层原则**：丹尼尔斯原生（Phase 1-4、2Q、E/M/T/I/R、赛后恢复规则、3+1 周计划形态）与本体系工程化扩展（recovery 正式化、块位/块间增量抽象、回补三场景、最小有效周期、坍缩阶梯、三硬门、季节性调整）在各分文档中分别标注，不把发明当教义。

## 3. 跨层决定

### 3.1 计划 = 政策，不是预测

数月计划对未来的详细判断是伪精度；回补场景（常规/疲劳/超量）是执行时决策不是设计时判断。设计时输出四样：**默认轨迹**（按常规场景物化的完整计划，用户看到的即它）、**决策策略**（回补判定规则集）、**硬边界**（三硬门，任何场景不可越）、**里程碑**（每阶段出口可检验信号）。详见 L3 分文档 §3。

### 3.2 执行时回路：一管线两产物 + 块界生成 + 每夜复盘（2026-10-27 拍板）

**一管线、两产物**：master plan 与 weekly plan 的生成管线融合为一条——政策层 L1→L2→L3 赛季开始跑一次，产物收缩为「政策包」（L2 意图 + L3 周骨架 + 块标记 + 回补/力量 policy + 里程碑对齐），**不含全期课表明细**（计划=政策的直接推论）；weekly plan = 政策包的逐周投影（L4→L5 执行时调用）。产物与生命周期分离：政策变更贵、留痕、过用户确认；课表廉价重生成。保留两产物的原因：政策/执行变更周期错位（融合滚动产物会让政策漂移廉价且不可见）、偏差可计算（R2/R3 信号=实际 vs 骨架，滚动产物没有基准线）、全跑道门（ACWR/带/taper）只能在整期上验证。

**生成粒度=块（3+1）**：L4+L5 每块到界一次生成整块课表（块内微阶梯/组数递进/吸收周需整块连贯）；例外——final_quality 含 taper 整段一次生成（跨周单调保证）、recovery 1-2 周单独成批。未执行部分在信号触发时廉价重生成；L3 滚动种子吃实际完成周，实际少练则下周包络自动收紧（已实现）。

**每夜复盘（确定性优先，零 LLM 常态）**：挂在晚间同步管线（race_detection→calibration→compute）之后，数据新鲜。绝大多数夜晚=确定性阈值判断（今日完成度/周量 vs 骨架/实际 ACWR/连续超量计数），结论「不动」；超阈值才升级。

**调整分级（计划可自动调，政策必须可见）**：微调（换课日期/单课减量）→ 静默+记录；中调（减质量课/块位回退）→ 通知用户；大调（提前吸收/重出 L3/L2）→ 用户确认。

**各层刷新频率**：L1 每晚自动（数据驱动纯函数）；L3 滚动种子每周滚动（吃实际周）；L3 骨架/L2 事件驱动（R2/R3）；L4/L5 块界生成+按需重生成。

信号源（生产已存在）：activities.feel（体感/RPE）、每日 HRV/RHR、session_class（质量课完成度、E/Q 配比）、配速漂移、PMC 的 ATL/CTL/form。**已知缺口：activity↔计划课的完成追踪为零（completed_label_id 全 NULL、推送 id 与计划 id 两套体系）——夜复盘的第一前置，启发式匹配先行**。

### 3.3 单赛制（2026-10-26 拍板）

V1 只针对一场比赛备赛。用户有多场参赛计划时由用户选定一场为 A 赛，其余场次忽略；测试赛（以赛代练）由系统主动安排为训练工具，不消费用户赛历的多场比赛。

### 3.4 季节天气不是结构性输入（2026-10-26 拍板）

race_date 已隐含季节，阶段结构由跑道与能力缺口驱动；天气影响发生在下游三层——**载荷层**（插入点暂缓实施：峰值块避开盛夏、夏季块位下调、冬季放大块量）、**内容层**（高温露点超阈切心率目标/挪清晨室内、冬季 I 课改造）、**执行层**（体感/HRV 自然吸收）。

**冬季 transition_quality 以 T 为主（拍板）**：I 课受冷天约束时调整次序=先降内容（I 份额下调、T 扶正，FM 特化下几乎无损）→ 仅当质量课整体不可执行才降时长（压缩让渡 final_quality，接受 I 缺位不搬家）→ 永不降顺序（R→I→T 不倒置）。R/strides 冬季适合保留。生效前提（待补）：训练城市月度气候常态进证据层（静态表）、场地可用性字段；「温度太低」判据须城市级（硬约束是冰面/-15°C 级/气道敏感），非泛泛「冬天」。

### 3.5 目标可行性阶梯（2026-10-26 拍板）

确定性纯函数 `assessGoal(evidence): GoalVerdict`（零 LLM），**锚=当前等效水平** `equivalents[goal.distance]`（#789 产物；比赛锚与校准锚取保守者——PB 是历史峰值，退化/进步双向都会算错，已否决）：

| verdict | 判据（阈值沿用 kernel 生产 doctrine） | 对计划的影响 |
|---|---|---|
| `supported` | gap ≤3% 且跑道 ≥12 周（gap≤0 同样 supported） | 按 A 目标正常出 |
| `aggressive_but_plausible` | 3%<gap≤10%，或跑道 <12 周 | A 照出；**峰值帽 ×0.95**（I8 门与 T 兜底同乘）+ 里程碑从严 |
| `multi_cycle_required` | gap>15%，或 >10% 且跑道 <16 周；**跑道 ≤6 周且 gap>0 强制此档**（与坍缩阶梯 §2.4 时间目标降级合一） | **不静默降级（2026-10-26 修正拍板）**：verdict 上浮 Coach Chat 明确告知（当前等效 vs 目标、gap），用户三选——坚持原目标 / 调整目标 / 换更远比赛；**B=equivalents×1.02 仅作建议值展示**，计划只按用户确认的目标生成；坚持 A 则照 A 构造并在 rationale 显式写风险；非对话入口返回 needs_confirmation 不代做决定 |
| `conditional` | 锚不可得（equivalents=null） | 引导先测一场，或按 C（安全完赛）出计划 |

**原则：系统不偷偷降低用户目标**——可以做体检、给建议，选择权在用户；aggressive 档的峰值帽 ×0.95 是安全边际非目标减配，但 Chat 中透明说明。三选项对话卡片属聊天路径实现，本决定定契约。

### 3.6 术语约定

L2 统一称**阶段划分层**（不用「意图层」）；契约 schema 名 `PhaseDivisionIntentSchema`（实现命名，代码 `phasing/intent.ts`）。

## 4. 层间契约

| 上游 → 下游 | 交接物 |
|---|---|
| L1 → L2 | 证据 JSON（月度画像/当前状态/学分/PB 校准/跑道目标） |
| L2 → L3 | 阶段清单（canonical/周区间/目标）+ 出口里程碑 + 体量带 + 块模式 + taper_weeks |
| L3 → L4 | 周骨架（每周 phase/km/LR/Q 配额+家族/km 预算/特殊周标记） |
| L3 → R2 | 回补策略 + 块边界标记 + 里程碑周对齐 |
| L4 → L5 | 具体课表（workout_structure） |
| R3 → L2 | 重发触发（新跑道/新目标参数） |

L2 与 L3 的耦合保留机制：**体量带**——阶段划分层给每阶段 min/max 周量护栏（证据推导），载荷层带内自由，无解回退重裁 L2。块模式指派同理随 L2 产出（阶段目标的直接映射）。
