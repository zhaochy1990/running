# 丹尼尔斯训练法·阶段划分设计决定

> 本文只记录讨论中**已拍板**的设计决定（2026-10-26）。未定、待验证、未经确认的方案不进本文档；
> 决定有变更时直接修改本文并更新日期。实证背景见 spike 记录（第五轮开放式对比，60 切片）。

## 1. 阶段枚举对齐丹尼尔斯（canonical 定稿 5 值）

阶段命名弃用 base/speed/build/marathon 旧枚举（Friel 铁三体系混搭，且 `marathon` 键名泄漏比赛距离），对齐 Daniels' Running Formula 原生词汇：

| canonical | 中文显示名 | 丹尼尔斯原文 | 职能 |
|---|---|---|---|
| `recovery` | 恢复期 | （无，我们的显式补充） | 赛后卸疲劳 |
| `foundation` | 第一阶段·基础期 | Phase 1 Foundation | E 跑+strides+轻爬坡，地基与防伤 |
| `early_quality` | 第二阶段·早期质量期 | Phase 2 Early Quality | R 重复跑，跑姿经济性与速度 |
| `transition_quality` | 第三阶段·过渡质量期 | Phase 3 Transition Quality | I 间歇为主，T 开始上量 |
| `final_quality` | 第四阶段·最终质量期 | Phase 4 Final Quality | T+M 比赛专项，自带 taper |

- **训练强度词汇沿用 E/M/T/I/R**（丹尼尔斯原生，内容层已在用）。
- 丹尼尔斯用编号是刻意的：阶段由内容定义，同一套 Phase 1-4 通用于 5 公里到全马，只是配比不同。

### 1.1 recovery 是正式阶段（对丹尼尔斯的工程化补充）

丹尼尔斯只在书里非正式提赛后休息；我们将其正式化，给它完整合同：

- 入口条件：距上场比赛 ≤14 天（或主观深度疲劳）
- 出口里程碑（可观察信号）：HRV 回基线、无残留酸痛、主观疲劳 ≤3
- 体量带：赛前量的 ≤60%；块模式：纯 E + strides

### 1.2 taper 不设阶段，是 final_quality 的必填属性

判断标准：正式阶段必须在主跑道占周数、有独立入口与出口里程碑、有体量带与块模式。taper 三条都不满足——出口就是比赛（整个计划的终点事件，不是阶段闸门）、无能力目标（兑现不是发展）、拆成阶段会把一个决策变成两个旋钮。

- `final_quality` 携带 `taper_weeks`（1-3 周，**结构参数归意图层**，影响跑道预算）
- 削减深度 30-50%（**量级参数归载荷层**）
- taper 作为必填属性后 LLM 不可再漏给（第五轮 LLM 曾整段丢失 taper 阶段）
- 用户可见性不降：周历末尾渲染「减量周」标签
- **B 赛 mini-taper 与赛中恢复 = 周级属性**（绑比赛周），不升阶段；正式 recovery 只保留计划开头的那个

## 2. 阶段划分 = 意图层（与载荷层解耦）

阶段划分只决定「哪段时间练什么能力、练到什么算数」，不输出任何周量数字。锚点/节奏/taper 深度等载荷决策独立成层；两层真正的耦合点（阶段周数 ↔ 载荷可行性）用**体量带**保住：意图层给每阶段 min/max 周量护栏（从证据推导），载荷层带内自由，无解才回退重裁意图层。

### 2.1 输入（五组，全部确定性代码生成）

1. 月度训练画像——session_class 聚合（4 月至今）：每月总 km、E 份额、Q 次数（含 LQ 拆分）、最长长跑（E+LQ 并算）、比赛场次
2. 当前状态——近 4/8 周滚动量、CTL/ATL/form、8 周最长距离、断练周数、距上场比赛天数、伤病史
3. 跑道与目标——weeks_to_race、A 赛距离/目标时间/improvement%、窗内 B/C 赛、每周可用训练日
4. PB + 校准区间——速度储备判断依据（免修论证全靠它）
5. 教义——丹尼尔斯锚定块（Phase 1-4、顺序律、FM 特化），在 prompt 层不在 payload

不输入：单课明细/laps（下钻是消费时的事）、PMC 仿真（那是验收门）、聊天上下文。

### 2.2 输出（一次小调用，约 12-15 字段）

1. **阶段清单**——canonical + 显示名 + 周区间/起止日期 + 能力重点 + 本阶段训练目标 + rationale（必须引用证据字段）；免修/压缩/合并裁决在此
2. **每阶段出口里程碑**——绑可观察信号的验收标准（示例：foundation 出口 = 25km 长跑连续两周无不适；transition_quality 出口 = 2 节 T 课 48h 内可恢复）
3. **阶段间 gate**——2-3 个绑信号的中期检查点
4. **每阶段体量带**——min/max 周量护栏，证据推导，非 LLM 发明
5. **块模式指派**——每阶段指定块形状（见 §3.4）

不输出：周量锚点、降周节奏落位、taper 削减深度、Q 配额、LR 进展、赛周激活（全在载荷层）；疲劳/超量判定（执行回路）；课结构（内容维度）。

### 2.3 判定与兜底

- **判断模型 = deepseek-flash**（第五轮实证：6/8 门全绿、三人结构分化 3/3；GLM-5.3-flash 结构退化+慢 6-9 倍出局，glm-5.3 深思考档超时出局，pro 已弃）
- **T 查表 = 结构缺省 + 包络校验 + LLM 失败兜底**（#732 终调和：查表不拿走判断）
- **确定性结构门**：跑道闭合（周数和=跑道、日期连续）、顺序律（recovery→foundation→early_quality→transition_quality→final_quality，可坍缩不可倒置）、赛后 14 天内完赛先恢复、FM 含专项期、final_quality 的 taper 属性合法（1-3 周）；不过 → 带违规清单重试 ≤2 次 → 落 T 骨架
- 设计时场景智能（LLM 价值区）：有氧学分够→压缩/免修 foundation；速度储备超目标→early_quality 折叠为 strides 维持；短跑道→阶段坍缩；伤退史→foundation 拉长

*状态注：第六轮（2026-10-26，3 运动员 × 2 模型 × 16 调用）已验证拆分形态：deepseek-flash 7/8 全绿、分化 3/3、意图层语义质量达标（里程碑可检验、rationale 引证）——**拆分不损失判断质量，本 scope 定稿**；GLM-5.3-flash 2/7+1 超时出局。两模型共同弱点=9 周坍缩（短跑道坍缩阶梯 §2.4 即其对策，待重测验证）。*

### 2.4 最小有效周期与短跑道坍缩阶梯（本体系扩展）

**最小有效周期**：阶段短于最小有效剂量则不设立（并入相邻阶段或降为副课维持）——1 周的 foundation 或质量期没有训练学意义。

| 阶段 | 最小周数 |
|---|---|
| recovery | 1 |
| foundation / early_quality / transition_quality | 2 |
| final_quality（含 taper） | 3 |

**坍缩阶梯**（按跑道周数）：

- **≥10 周**：完整五阶段阶梯，学分压缩由判断层自由裁量
- **7-9 周**：≤4 阶段；先砍 early_quality（折叠为 strides/R 维持副课）→ 再砍 transition_quality；foundation≥2 与 final_quality≥3 底线不可再砍
- **≤6 周**：只有 [recovery?] + final_quality 直达专项+减量；时间目标由可行性评估降级为 B/C——**训练计划永远给，被拒绝的只是不切实际的时间目标**
- **≤3 周**：final_quality 即赛前微周期（taper+激活为主）

## 3. 载荷规划：块机制

### 3.1 块（block）是载荷的基本单位

- 块 = 3+1（或 2+1）周期：3 个递进周 + 1 个吸收周
- 每块两个数：**块位**（这块练多大量）与**块间增量**（下一块比上一块 +3~8%）
- 吸收周深度：计划内 -22~30%；疲劳警戒更深（-35%+，属执行回路场景）

### 3.2 「每周 ≤10%」规则退役

10.0% 与 10.5% 无实质差异；该规则从硬门降为块内阶梯的缺省系数。替换为三个有依据的硬门：

1. **急慢性比 ≤1.3**（本周实际量 / 近 4 周均值；即 PMC 已算的 ATL/CTL 口径，>1.5 高危）
2. **单周尖峰 ≤ 前 4 周均值 ×1.5**
3. **月度块对块 ≤ +20~25%**（4 周滚动总量环比）

### 3.3 回补规则（降周后下一块回到哪）

缺省（常规吸收周）：**块重启**——下一块 = 上一块各周 + 块增量。示例：100/105/110 → 吸收周 77 → 下一块 105/110/115（w5=105），**不是**回 110、更不是 77×1.1=85，也不是进度线续走 113。急慢性验算 105/98=1.07，最稳且回补最温和。

另两种场景由执行回路选择（见 §4）：疲劳触发→重复上一块块位；超量适应→放大步长（+8~10%）且受硬门约束。

### 3.4 阶段目标决定块形状

- foundation：递进块（量是主变量）
- early_quality：递进块，R 质量开始占位
- transition_quality：递进块但增量放缓，块内质量负荷增长
- final_quality：**平台块**——块位不涨、在峰值位持平，块间增长的是 M 配速长距离负荷（丹尼尔斯全马计划经典形态：量中段见顶持平，换内容不换量）；末块转削减（taper 属性）
- recovery：低量块

## 4. 计划 = 政策，不是预测

数月计划对未来的详细判断是伪精度；**回补场景（常规/疲劳/超量）是执行时决策，不是设计时判断**。设计时无法预知第 N 周的身体状态，只能把「到时候怎么判」定成规则。

### 4.1 设计时输出四样东西

1. **默认轨迹**——按常规场景物化的全程块计划（用户看到的完整计划即它）
2. **决策策略**——回补场景判定规则集 + 降周深度规则
3. **硬边界**——§3.2 三硬门，任何场景不可越
4. **里程碑**——每阶段出口的可检验信号，策略执行的检查点

### 4.2 执行时回路（三级时间尺度）

- **课/日级**：读体感、HRV、睡眠 → 周内微调（换课、强度帽、单课降级）——weekly plan 职责
- **块边界级（约每 4 周）**：评估本块完成度 → 套策略选回补场景 → 物化下一块周数字
- **结构级（罕见）**：伤停超阈值、比赛改期、目标变更 → 重发意图层（一次小调用，便宜）

### 4.3 信号源（生产已存在，无需新建采集）

activities.feel（体感/RPE）、每日 HRV/RHR、session_class（质量课实际完成度、E/Q 配比）、配速漂移、PMC 的 ATL/CTL/form。

## 5. 季节天气（本体系扩展；丹尼尔斯原书把环境当执行层调整因子）

**决定：天气不是阶段划分的结构性输入**——race_date 已隐含季节（春赛专项期必在冬末、秋赛训练期必过盛夏），阶段结构由跑道与能力缺口驱动，天气影响发生在下游三层：

1. **载荷层**（插入点，暂缓实施）：峰值块避开盛夏、夏季月份块位下调、E 份额上调；冬季适合放大块量（冬训传统）
2. **内容层**：高温/露点超阈值时质量课目标从配速切心率、挪清晨/室内
3. **执行层**：当天天气经体感/HRV 被运行回路自然吸收

### 5.1 冬季 transition_quality 以 T 为主（2026-10-26 拍板）

春赛的 transition_quality 必然落在深冬；I 课受冷天约束时的调整次序（**不影响阶段划分与块模式**）：

1. **先降内容（默认）**：I 份额下调甚至归零、T 扶正为主角，实际训练安排以阈值课为主而非 I 间歇——FM 特化下几乎无损（教义本要求 FM 的 I 保守，T 才是马拉松最相关的强度）
2. **再降时长（仅当质量课整体不可执行）**：压缩 transition_quality 让渡 final_quality，接受 I 缺位而非搬家（final_quality 严控 I，不可倒序补课）
3. **永不降顺序**：R→I→T 递进律不因天气倒置

R/strides 短触感冬季适合保留（神经与经济性维护剂，低疲劳，丹尼尔斯 Phase 1 原生内容）；I 课冬季化改造（段落缩短、组间恢复加长、目标切心率/努力度、挪室内、热身延长）属内容层。

**生效前提（待补）**：训练城市月度气候常态进证据层（静态表，现有月度画像不带）；场地可用性（跑步机/室内馆，运动员画像暂无此字段）。「温度太低」的判据须城市级（-5°C 配热身 I 仍可跑；硬约束是冰面、-15°C 级极寒、气道敏感人群），非泛泛「冬天」。
