# 文件 POC 的实测与内容质量

执行于2026-11-15。真实资料、逐条审查和完整模型响应只保存在本地。这里记录不含私人原文的结论；本轮没有生产写入。

## 质量判断

第一版存在实质性归属错误：历史周复盘写明没有本人主观文字，模型却把客观分析标为本人陈述。该版不能作为合格画像。初版模型材料还遗漏了已采集的负荷与恢复序列，候选主要是选取记录的复述。

文件版修正为：代码直接抽取可确认的活动本人原文；不将作者不明、混有教练分析的旧周复盘当成自述。完整活动窗口统计由代码生成，已有能力估计保持估计身份，负荷和恢复测量保留来源日期及缺失语义。关键数值另用独立脚本对原始快照复算。

现阶段得到的是有证据的训练经历、近期状态与少量综合认识，能初步描述这个用户；还不能宣称获得了稳定个体规律。第一轮文件版的候选过于重复事实与边界，随后缩短正文、加入完整周序列，检验是否更容易看出训练经历随时间的变化。

## 分层带来的认识

- 知识类型与生命周期必须分开。自述可以只描述一次体验；估计可能不断滚动；历史记录也可能更正。
- 汇总“最近多少次／多少公里”属于滚动窗口；具体某场活动属于历史。把所有训练历史放成永久不变的一层会混淆两者。
- 空的长期层是一项有效结果。本快照没有足够本人陈述和验证材料，不能为了补齐层级产生固定偏好或体质标签。
- 先保存可追溯条目，再按生命周期／主题重组同一批内容，已足以测试分层思路；POC无需先实现正式数据库。

## 本轮验证

- 包独立编译；只依赖共享客户端、契约日期和schema库，不改Go、Coach或训练计划运行时。
- 本地测试覆盖跑步／力量隔离、上海日期时段、原文归属、来源更正／撤回以及同一批结论的分层重排。
- 真实快照生成本地JSON／Markdown，模型响应、token用量与耗时单独保存；未返回金额。
- 撤回试验只作用于快照副本；原始输入与历史文件保留作对照。文件保存不意味着已有生产级失效保护。

## 下一轮优先事项

先补充可靠的本人陈述、训练／参赛背景与来源元数据，再检验个体关联是否比已有统计提供额外认识。定量方法、效应验证和支持程度继续由后续决策票依据POC结果完善。完整自动调度、Go存储、消费接入和生产迁移仍不在本轮范围。

早先隔离Go／MySQL／Coach试验曾验证技术链路，但已按用户收缩范围从当前代码撤除；其历史结果不作为本文件POC的功能或质量保证。
