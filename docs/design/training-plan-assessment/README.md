# 训练计划与运动能力评估 UI 讨论记录

记录日期：2026-11-16。保存本轮讨论的流程与文案，供后续设计、契约和实现使用。

直接用浏览器打开 [HTML 预览](preview.html)，无需安装依赖、启动服务或联网。顶部选择器是讨论工具，不是正式产品界面；卡片依次展示连续阶段，不代表产品同时展示三个页面。按钮只更新本地演示状态，不提交任务或修改训练安排。重新加载预览会重置场景。

关联：[训练画像持续更新与计划读取解耦](https://github.com/zhaochy1990/stride-devops/issues/960)、[Coach 与训练计划读取画像的新鲜度与使用契约](https://github.com/zhaochy1990/stride-devops/issues/965)。本记录不代表整张决策票已经收口，也不表示生产已实现。

## 已确定的流程与表达

### 创建训练计划

1. 用户发起创建，尚无可用评估或需要等待评估时，显示“正在评估你的运动能力”和进度条。
2. 评估完成后自动进入计划生成。在同一张进度卡中，上方保留“运动能力评估已完成”和 100% 满格进度条，下方展示“正在制定你的训练计划”与当前阶段进度。
3. 生成结果继续遵守已有的用户确认规则，确认后才应用训练计划。

已有有效、适用且没有未处理相关变化的评估结果时，可以直接进入计划生成，无需重复等待。不单凭画像发布时间判断新鲜度；当前负荷、恢复、伤病限制仍需单独读取。

用户提出精简“稍后回来”和“取消本次创建”两个按钮，当前草案已移除；单次训练修改流程也采用相同的等待布局。离开页面时任务继续、返回后恢复进度，是与这一精简配套的设计提案，持久化与恢复契约仍待确认。完成评估才显示 100%；进行中的阶段不虚构精确完成百分比或剩余时间。

### 修改或取消某一次训练

等待可用的运动能力评估，再结合评估结果与当前训练计划判断影响，展示调整方案和对后续安排的影响，遵守确认后应用的规则。

“取消某次训练”是对课表的修改，与已移除的“取消本次创建请求”按钮含义不同。不能因为只是取消一节课就跳过评估。

### 完全退出当前训练计划

用户明确退出当前计划后，不再生成后续计划。这一操作不依赖运动能力评估。预览包含退出确认及退出完成状态；具体确认文案作为草案保留。

退出计划与修改单次训练都不会停止对运动能力和运动习惯的持续评估。退出时如何处理已生成的未来训练，尚未决定，不能据此推断会删除或取消它们。

### 面向用户的用语

使用“运动能力”“运动习惯”，不在用户界面中使用“运动画像”。技术讨论仍可使用训练画像这一领域概念。

## 预览中的状态草案

| 状态 | 展示方向 | 确认程度 |
| --- | --- | --- |
| 首次评估 | 能力评估 → 计划生成／修改影响评估 → 查看结果 | 主流程已确定；细分步骤文案是示意 |
| 已有可用评估 | 显示已完成，直接进入计划处理 | 允许复用的原则已确定 |
| 尚未连接手表／没有运动记录 | 提示补充前置资料，下一阶段等待 | 提示文案及自动续接细节待确认 |
| 评估失败／计划处理失败 | 保留请求，提供当前阶段重试 | 待确认；不得展示成成功或允许应用空结果 |
| 离开后返回 | 恢复同一次请求和后台实际进度 | 待确认持久化、查找和恢复契约 |
| 网络断开 | 标明无法获取进度，重新连接后恢复实际阶段 | 待确认；断网不等同于任务失败 |
| 退出计划 | 确认退出 → 已退出，持续评估仍继续 | 不等待评估的原则已确定 |

预览中的检查清单是说明阶段的示意，不是已经确定的后端事件名、百分比分配或任务状态协议。所有重试按钮仅切换演示场景，不证明真实任务可以恢复。

## 尚待决定

- 创建计划时，如果既没有可用评估也没有评估任务，是否由创建请求编排入口要求 Go 确保独立评估任务已经安排。用户要求先看完整 UI，尚未批准这一触发补充。
- 等待请求如何持久保存、合并重复请求、返回后恢复；失败与超时如何处理。
- 计划处理期间评估或来源变化时怎样重新校验；查看和应用结果前的有效性检查。
- 退出计划对已经生成的未来训练安排有什么影响。

## 本地验证

HTML 使用内联样式与脚本，禁止联网，不读取真实用户数据，不依赖对话宿主。检查创建／单次修改的各状态切换、重试、退出流程、第一步 100% 在第二步进度上方，以及窄屏和深色显示。验证范围是讨论预览，不是生产端到端流程。
