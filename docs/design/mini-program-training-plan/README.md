# 微信小程序：赛季训练计划审阅原型

记录日期：2026-11-18。归档本轮确认的计划概览、目标评估、阶段目标与里程碑、每周安排 UI，供后续小程序实现对照。

直接用浏览器打开 [HTML 原型](preview.html)。单文件内含样式、脚本和展示数据，不需要安装依赖、启动服务、联网或登录。默认进入「计划概览」；桌面左侧入口是讨论工具，不属于小程序产品 UI。

这是本地探索原型，不是已实现的小程序页面。没有 API 请求、生产写入或持久化。「启用计划」只改变内存中的演示状态，刷新即重置；「调整计划」只演示输入入口，不生成新版计划。

## 已确认的界面

- **标题与日期**：使用「赛事名＋目标＋计划」，示例为「无锡马拉松250突破计划」；备赛日期放在副标题。不再单列「新计划」和周数／阶段数／峰值三项统计。
- **目标评估**：精简绿色区域，默认只显示评估结论和「查看评估依据与备选目标」。展开后显示提升要求、历史支持、A/B/C 目标及检查条件。
- **15周训练节奏**：柱状图切换周跑量与长距离目标，阶段柱色、下方阶段色线和阶段标签保持一致。不铺阶段背景、不另列阶段时长条，峰值标在图内。没有独立单周详情框。
- **每周安排的发现入口**：顶部固定保留「计划概览／每周安排」；图表下方另有「查看每周训练安排」入口。
- **阶段内容**：横向切换五个阶段，选中项使用同源阶段色、浅底和下划线。展示目标、默认可见的里程碑、力量和恢复建议。不重复放跑量小图，不显示「未达标时如何调整」。总体训练原则默认展开。
- **每周安排**：以周连续向下浏览，每天一行显示训练名称与距离，单课细节默认收起；支持快速跳周、返回阶段目标。展开单课后按结构展示热身、重复组、恢复、放松、配速及心率限制。

## 数据和 schema

本次指定输入为工作区中的 `prototypes/chat-plan-generation/wuxi-2027-plan.json`（工作区父目录中的本地文件，不是仓库内路径）。HTML 的 `#plan-artifact` 内嵌了其中用于显示的五个字段，内容逐字段保持一致：`plan`、`goal_assessment`、`policy`、`skeleton`、`weekly_docs`。未复制未显示的 `facts`、`anchor`、`audit` 等原始快照。

| 展示 | 数据来源 |
| --- | --- |
| 比赛、目标、起止日期、周数 | `plan.goal`、`plan.start_date`、`plan.end_date`、`plan.total_weeks` |
| 五个展示阶段与日期 | `plan.phases`，按 `plan.weeks.phase_name` 和日期关联 |
| 每周跑量与峰值 | `plan.weeks.target_weekly_km_low/high` |
| 长距离目标、递进／吸收／减量／比赛周 | `skeleton.weeks.lr/role`；缺失长距离标为未提供，不当作零 |
| 阶段目标、力量与恢复 | `plan.phases.focus/strength/recovery` |
| 阶段里程碑 | `policy.milestones`，按该周所属策略阶段关联 |
| A/B/C目标与条件 | `goal_assessment.abc_gates.*.target/conditions` |
| 每日课表 | `weekly_docs.sessions`，按 `week_index` 关联 |
| 单课步骤与重复次数 | `sessions.spec.blocks[].repeat/steps` |

数据包含 **15周、5个展示阶段**，只有 **前4周**存在每日课表。后11周只显示周跑量、长距离和质量课配额，明确标注「每日课表尚未生成」，不补造每日训练。

评估的中文结论与依据摘要是对本例 JSON 的界面表达，并非评估算法；A/B/C 检查条件直接展示原始 `criterion`，因此保留英文。此文件固定展示这份样例，不是可以导入任意计划的通用读取器。

### 原始样例的差异保留

- `policy` 为四段，最后一段包含减量；`plan.phases` 将减量独立列出，形成五个展示阶段。专项与减量共用的里程碑有明确标注。
- 部分文字目标／里程碑与周目标存在不一致，例如基础期文字或条件提到85–90公里，前4周目标实际为72.8、75、77.3、54.6公里。图表按周目标绘制，文字按来源显示；原型未修订源计划。
- 减量期 `focus` 沿用了专项期说明，力量训练的结构字段与文字建议也可能不一致。这里保留来源供设计讨论，不代表原始样例已通过严格 schema 或训练处方验收。

## 本地验证

使用真实 Chrome 浏览器打开 `file://` 文件，在360、390、430、860px视口检查概览与每周安排无横向溢出；验证目标评估展开、五阶段切换、图表指标与空值、阶段里程碑、15周列表、前4周真实日课、重复组展开、跳周、结果卡返回、调整入口、启用及刷新重置。没有脚本错误或 HTTP(S) 请求。

归档清理前后，390px手机区域的概览、阶段详情、每周安排三张截图像素一致。本次验证范围仅为 HTML 原型，不包含小程序运行时、生产 API 或真实计划启用。
