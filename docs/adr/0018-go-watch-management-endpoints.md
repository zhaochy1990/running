# Go `cmd/api`: watch-management endpoints (GET/DELETE `/api/users/me/watch`)

The Go `cmd/api` so far only *connected* a watch (`POST /api/users/me/watch/login`, ADR 0013). We add the two endpoints that manage an **already-connected** watch — the Python `WatchPage` surface — as a coexisting port with contract parity: `GET /api/users/me/watch` (status) and `DELETE /api/users/me/watch` (disconnect). Manual sync-trigger and single-activity resync stay out of scope (they belong to the deferred sync-endpoints port).

## Decision

- **`GET /watch` returns the exact Python `WatchInfo` JSON** — `{provider, provider_display_name, logged_in, email, device, last_sync_at, capabilities[]}` — so a later browser cutover is just routing. No provider bound → `200` with nulls and `logged_in:false`.
- **`cmd/api` now reads the watch-data MySQL tables** (`activities`, `sync_meta`, `provider_credentials`) to serve status. This *expands* the ADR 0012/0013 framing, where `cmd/api` held only its own app-level tables (`user_profile`, `user_onboarding`) plus RabbitMQ. It is safe because Go owns one canonical MySQL schema shared by writer and reader (ADR 0006): `provider`+`logged_in`+`email` come from `provider_credentials`, `device` from the latest `activities` row (`ORDER BY date DESC LIMIT 1`), `last_sync_at` from `sync_meta[last_sync_time]`, and `provider_display_name`+`capabilities` from the provider registry.
- **`last_sync_at` gets a new writer.** Go's `watch_sync` handler previously stored only the `last_label_id` cursor. The shared `watchsync` handler now stamps `sync_meta[last_sync_time]=now(UTC RFC3339)` on **any** successful sync (one provider-agnostic place). Best-effort: a failed stamp never fails an otherwise-successful sync. Chosen over deriving from job rows because `sync_meta` is durable per-user state that survives job-row pruning.
- **`logged_in` stays presence-only** (`len(provider_credentials.secret) > 0`), matching Python's `is_logged_in`. No "token expired / re-authentication required" state — detecting expiry needs a live provider round-trip on the status hot path and new frontend UX. Credential-health is a deferred, separately-designed feature.
- **`capabilities` reflect the Go registry, not Python.** Go's COROS adapter currently advertises only `sync_hrv_detail` (push/delete are unimplemented placeholders), so `GET /watch` returns fewer chips than Python for COROS. This is honest to the Go implementation rather than a hard-coded parity list.
- **`DELETE /watch` deletes the `provider_credentials` row and resets `watch_ready→false`, retaining all synced data.** No credential row → `400` (nothing bound); a row exists → delete it and return `200 {ok, provider}`. Because Go has no `config.json` default-provider state (binding *is* the credential row), Python's `409` "bound-but-not-logged-in" case cannot arise, so it is not implemented. Disconnect clears credentials directly via a store method; `Provider.Logout` stays a no-op for now (there is no server-side token to revoke).
- **`completed_at` is left untouched on disconnect** — a deliberate divergence from Python's `watch.py`, which resets it. `completed_at` is the onboarding gate (`AppRoutes.tsx` routes on it) and is owned by the not-yet-ported sync-complete flow; in the Go flow it is always null today (ADR 0013), so resetting it is a no-op. The watch-management task resets only `watch_ready`, which it legitimately owns.
- **Handlers extend the existing `userRoutes` registrar** (ADR 0013), reusing the authed group + user-tier JWT. `display_name`+`capabilities` are fetched through a new `ProviderInfo` port satisfied by a cmd-layer adapter (mirror of `providerLoginAdapter`), keeping `internal/api` free of `provider`/`registry` imports.

## Consequences

- **HARD follow-up (gate invariant):** once the sync-complete port lands and begins writing `completed_at`, `DELETE /watch` **must** also reset it — otherwise a disconnected user stays `'ready'` (in-app, watch-less), breaking the "in the app ⟺ has a watch" invariant.
- **Coexistence follow-up:** the frontend still calls per-provider `/coros/login`+`/garmin/login` and Python's `GET/DELETE /watch`; cutting the browser to the Go endpoints is a separate routing change (also gated on the `coros_ready → watch_ready` rename tracked in ADR 0013).
- **Capability divergence is visible:** until the Go COROS adapter implements push/delete, the WatchPage would show fewer capability chips under Go than under Python. Acceptable during coexistence; closes as adapters gain features.
- **`Provider.Logout` remains dead code.** When a provider grows real server-side session revocation, disconnect should route through `Logout` instead of the direct store delete.
