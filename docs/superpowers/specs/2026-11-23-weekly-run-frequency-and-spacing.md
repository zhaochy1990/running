# 周训练频率与训练日分布

2026-11-23 · 设计与实施验收

生成器每周要回答两个问题：运动员适合用几天完成几堂跑课，以及这些课放在哪些日期。用户提供可用时间和每周可跑天数上限。教练根据运动员的训练能力和本周任务决定频率，排课器负责验证每堂课在日历上的位置。

## 现状与取舍

在一次生效课表的只读核对中，连续三个普通周都有四堂课。按周一到周日排列，三周均为「长轻松跑、阈值、休、休、休、短轻松跑、长跑」。两个可见周界均连续跑四天，最密集的一段依次为长跑、约 86 分钟的轻松跑、阈值课。三周审计均记录最长连休三天，仍允许生成完成。

现有周分配器按周量、长跑和质量课预算、轻松跑时长带以及用户天数上限选择轻松跑槽位。常规排课从周一依次填平日，预留周六轻量位和周日长跑。频率审计按自然周计数。实现入口见[周量分配](../../../src/coach_agent/src/graph/master_plan/phasing/content/allocate.ts)、[日期排位](../../../src/coach_agent/src/graph/master_plan/phasing/content/schedule/scheduler.ts)和[现有审计](../../../src/coach_agent/src/graph/master_plan/phasing/content/danielsAudit.ts)。

只调整提示词无法约束最终日期和模板兜底。给所有人统一设置最长连跑或连休天数，会误伤每周两跑、六跑或只能连续几天训练的人。采用两步方案：先在给定课包和频率下找合理日历，再让周骨架明确提出个体化频率并用同一个排课器验证。两步都沿用既有周量、负荷及课程规则。

## 一、给定课包，选择可执行的日期分布

1. **生成候选。** 接收本周课包、边界日历、可用日期、固定事件和每周天数上限。沿用北京时间（Asia/Shanghai）划分日和周，历史实绩直接使用 Provider 的 `Activity.shanghaiDay`。保持跑课数、跑步日数、课程目的及长跑与质量课配额，枚举可用日期组合并比较课型落位。四跑周最多有 35 种日期组合，日期相同时仍须比较关键课的位置。轻松跑时长可在既有时长带和周量容差内重新分配。不能靠删课、添加短课或双练来消除连休。
2. **先检验可行性。** 尊重不可用日、已锁定或已完成的课程、比赛固定日期及既有赛周例外。采用真实落位计算时长带、长跑前日限制、质量课间隔、双练准入、逐日负荷与周量。质量课恢复间隔也要检查周界。只有通过原有硬约束的候选可进入比较。
3. **比较可避免的集中。** 对同一边界下受候选影响的日期，计算最长连续跑步天数、最长连续无跑步天数，以及包含长跑或质量课的连续三日窗口的最大负荷和。三日和使用已有逐日剂量，同日多课按日合计。若候选在三项上均不差且至少一项更好，淘汰被超过的方案。其余有取舍时，先保护关键课附近的恢复，再比较日期分布；完全等价时用稳定顺序选取。审计保留候选指标与选择原因。三日和用于同约束候选间排序，不设统一生理阈值。
4. **处理边界。** 同一生成窗口内比较相邻周的组合；首周接上已知历史，滚动续排接上实际完成记录及仍生效的相邻课程。已发生日期优先使用可靠实绩，未来锁定日期以生效安排为准。已有负荷种子与日历边界分别传递，模板重试沿用同一份上下文。未知日期标为未知，连续段只报告可观测部分；以后续周补齐时复核交界，只调整可变日期。
5. **区分集中与无解。** 若集中来自固定日期、可用窗口或明确的恢复安排，输出最佳可行日历和具体约束。若所有候选违反硬约束，返回受冲突的日期和约束，交回上游调整。审计负责解释最终选择，不能以警告放行有明确更优解的扎堆安排。

**跨入口的数据归属。** 第一张票负责把确认请求里的具体可用窗口、不可跑日、单课时长上限和双练许可带到首次排课，并在赛季计划中保存，供滚动续排还原。小程序将未指定日内时段表示为 `available_training_windows: []`，此时从一周七天扣除禁跑日得到候选日。有明确可用窗口时同时满足窗口和禁跑日限制。新候选同时满足用户许可和既有训练规则。常规长跑的周日限制与用户不可用日冲突时，按硬约束无解处理。已有计划若只存天数上限，沿用可确认的约束，并记录具体日期未知；若连上限也缺失，则沿用已有缺失输入处理。对照[请求可用度](../../../src/coach_contract/src/master_plan/contracts.ts)、[计划存储契约](../../../src/coach_contract/src/master_plan/policy.ts)和[续排读取](../../../src/coach_agent/src/graph/rolling/storedContent.ts)。验收需从真实生成入口传入一个禁跑日，在保存后重新读取并验证续排同样避开；覆盖空窗口数组，以及 UTC 周日深夜、北京时间周一凌晨的活动正确计入新周。

### 日期分布的回放验收

| 场景 | 通过条件 |
| --- | --- |
| 连续三个普通四跑周 | 固定上述课包、周量与频率，比较把长轻松跑从周一移至周四的候选。若候选通过硬约束且上述三项指标均不差并有改善，原排法必须被淘汰。可选其他同样合理的日期。对照日历的完整周界最长连跑 4→2 天，周内最长连休 3→1 天。 |
| 可行性已独立确认的四跑正例 | 用固定负荷种子与脱敏课包，先用既有硬校验独立证明原日历和更分散日历都可行，后者在三项指标上均不差且至少一项更好。再从生成入口断言淘汰原解，输出有改善的日历；对照未通过硬校验或改善未发生均判测试失败。 |
| 每周两跑、六跑；可用日均相邻 | 分散两跑；六跑允许合理连跑并检验关键课恢复；仅相邻日可用时列出具体受限日期。三类均保持原定频率和可用窗口。 |
| 首次生成、滚动续排、模型失败转模板 | 同一输入与边界采用同一可行性和分布规则，重算负荷。覆盖跨周与跨生成批次、未知边界、锁定课程、赛周、硬约束无解。回放报告列出前后日历、连跑、连休、关键课三日负荷与既有校验结果。 |

## 二、在周骨架决定本周频率

| 概念 | 所有者及口径 |
| --- | --- |
| 每周最多可跑天数 | 用户可用度，按北京时间日期去重，是硬上限。 |
| 本周目标跑步天数 | AI 结合运动员证据与阶段目标推荐，每周独立给出，可低于上限。 |
| 本周目标跑课节数 | 本周要完成的跑步课程数。一次双练算两节、一个跑步日，沿用既有双练准入；力量等非跑课另计。 |

**证据与决策。** 从有可靠覆盖的近期完整周提取实际跑步天数、跑量、典型单课时长、长跑完成情况，并纳入可信的恢复、中断和运动员明确给出的时间约束。保存所用观察窗口和有效周数。缺数时说明覆盖不足，使用已有可信资料给出保守候选；漏传或不完整周不得直接计为零跑。以稳定频率为起点，结合阶段、本周总量及关键课提出目标天数、节数和选择理由。相同证据与周任务下，稳定频率能承载课程且恢复合适时优先延续。增加或减少一天需指明本周变化及运动员证据。

**可行性反馈。** 将两项目标连同周量、长跑和质量课配额传给课包生成、量账分配、模板和第一步的排课器。普通轻松跑现有时长下限可能使“五跑拆短”不可行；此时记录冲突，再比较有证据支持且不超过可用度的相邻频率。若仍不可行，交回周骨架修改周量或课程构成，再计算。频率、课包或日期有变更，须用最新候选重算，成功后校对最终日历的实际去重天数、课数与最终目标一致，保留变更理由。

**首次与续排。** 首次生成在周骨架保存频率决策及依据，只有已展开周才有可执行日历。滚动生成用最新完成情况重新评估待生成周，保留已完成及锁定日期。新增字段遵循现有计划契约版本兼容机制；旧计划仍可读取、展示，续排缺失的新字段在待生成周补算。独立的伤病维持周沿用专用策略，本次验收覆盖常规赛季计划生成及其滚动续排。两张票交付的是未来生成与续排能力，存量生效课表的调整沿用已有确认流程。

### 训练频率的回放验收

| 场景 | 通过条件 |
| --- | --- |
| 上限相同、证据不同 | 固定可跑上限为 7。一例近期稳定四跑且四跑能容纳本周任务，延续四跑；另一例近期已稳定承担更高频率、本周任务也支持，能选择更高频率。提供实际周证据、频率和可执行日历。 |
| 同一运动员，阶段或完成情况变化 | 覆盖一次有证据的增频和一次降频；理由能追溯到观察窗口与具体任务。稳定四跑者不会仅因可用七天而升频。 |
| 课数、天数、兜底与兼容 | 合法双练正确计数；不具备双练条件时不得借双练挤课。主路径与兜底结果均与最终目标对账。历史不完整与旧计划续排可解释、可读，已锁定课程不被移动。 |
| 所选频率装不下周量 | 可行时回报采用相邻频率的原因；硬约束仍冲突时返回上游调整。最终候选重新通过第一步验收，回放中记录失败原因或合格日历。 |
